## 2. 時系列で見た到達点

### 2.1 方針の固定（〜6/22）

出典: `google_doc/MD/260622_今後の方針/`

研究の中心を次のように置いた。

- LEO 衛星間光通信で、熱ひずみ由来の LOS バイアスが粗捕捉性能に与える影響を評価する
- 熱ひずみを固定誤差ではなく、軌道位相・日照・電源モードに依存する時間変動バイアスとして扱う
- 予測した熱 LOS を scan center 補正に使う
- 軌道予測誤差は、ICSO 時点では本格モデル化せず、外乱として真値側に載せる

最終主張の骨格もこの時点でほぼ書けている。

1. 熱由来 LOS は粗捕捉に無視できない
2. 熱環境・軌道位相・電源モードから一部は予測可能
3. 予測補正で探索範囲・捕捉時間を減らせる
4. すべての指向誤差を消す手法ではなく、予測可能な熱成分を減らす手法である

出典: `260619_Femapことはじめ`、`260624_Femap解析`、`260625_Femap六面体`、`260629_Femap深化`、`260630_光RGコメント`、`260701_ToDoリスト`

到達したこと:

- 温度場 → 熱応力・熱変形 → STT/LCT 基準面の相対回転 → LOS 角、まで通る

- 「時変を狙うなら日照/食遷移 + LCT 発熱の方が、軽量モデルの必要性も説明しやすい」という研究デザイン上の判断が残っている

### 2.3 PAT 接続と「熱補正が効くか」の確認（7/2〜7/5）

出典: `260702_パターン解析`、`260704_軽量モデル構築`、`260705_軌道予測誤差導入`、`memo_in_repository.md`

到達したこと:

- Femap 由来 `stt_relative_los` / far-field PAT LOS を scan center 誤差に入れる
- 比較ケースを整理
  - no correction
  - thermal truth correction
  - thermal + nonthermal（補正なし / 熱だけ補正）

ここでの重要な注意:

### 2.4 軽量モデルの成立と自動化（7/8〜7/11）

出典: `260708_軽量モデル検討`、`260711_モデル先行研究`

研究としての最大のジャンプがここにある。

#### SUNFACE モデル

観測事実:

- パネル中心温度（特に太陽指向面）と LOS 支配軸の相関が強い
- さらに、**太陽指向面と反対面の温度差**が支配項になるケースがある（例: PY 太陽指向で反対側 MY が Black のとき）

モデル形（要約）:

- 支配軸は太陽方向（サンセンサ既知を前提）で選ぶ
- 主特徴量は `T_sunface`、`T_sunface - T_opposite`、必要なら `T_sunface - T_ref`
- within-case のリッジ回帰で係数を合わせると、Femap 真値に極めて良く合う
- 係数 `a3`（温度差項）はケース横断でおおむね同オーダー（メモ上 20〜30 µrad/°C 前後）

解釈:

- STT と LCT が対向パネル配置のとき、差動熱膨張 → 構体曲げ → 相対 LOS、という因果が一次式で見える
- static bias では追えない時変成分を、少数の温度特徴量で説明できる
- これはアブストの「物理ベース予測」層そのもの

#### ケース拡充と自動化

- case 03〜15 程度まで太陽方向・表面特性・内部発熱配置を振る
- TD mapper / Femap 実行の自動化を段階導入
- Student Edition のノード数制限、mapper 混線、sav 二重登録、光学特性未反映などの運用バグを踏んで修正

研究上きわめて重要な学び:

> TD の温度場が間違っていると、Femap / LOS / 軽量モデルまで一気に誤る。  
> ケースを増やしたら、まず温度場の妥当性チェックを通してから下流に流す。

光学特性がパネルに載っていなかった件（case 11/12 の係数一致など）は、まさにその典型で、メモがなければ原因特定が遅れていた可能性が高い。

#### 結果の物理的一貫性（再解析後）

メモ上の読み（数値は OCR 由来の概数）:

- MY/PY: Y が主因、X は小さい
- PX/MX: X が主因、符号は反転
- MY 面の熱光学特性（Black / 0.5 / alodine）が Y 方向 LOS 変動幅に直結
- 内部発熱位置は ptp より mean・波形（バイアスと過渡）に効く

感度の向きが物理的に筋が通っている、という段階まで来ている。

### 2.5 新規性の位置づけと配置感度（7/11〜7/12）

出典: `260711_モデル先行研究`、`260712_JANUS研究`、`260712_LCT配置変更`、`260712_ToDoリスト`

#### 先行研究との差分

最も近い: JANUS Optical Head の温度依存 LOS モデル

- `LoS(t) = K ΔT_walls(t)`（Optical Wall と Baffle Wall の温度差）
- 地上試験で係数を取る
- 光学ヘッド単体・衛星バス上の STT–LCT 相対 LOS・光通信粗捕捉ではない

整理した差分（現時点の主張候補）:

- JANUS: 実機光学機器で、温度センサから LOS を一次推定できることを示した
- 本研究: それを**衛星バス上の STT–LCT 相対 LOS**と**光通信粗捕捉（scan center FF）**へ拡張する
- 「温度勾配が差動熱膨張と曲げを介して LOS を変える」こと自体は既知
- 「複雑な衛星温度場の中で、どの ΔT が相対 LOS の主説明変数か」を配置・熱環境込みで示す点が差別化になりうる

その他の周辺:

- 観測衛星の Fourier / NN 系: 入力が温度センサ中心ではないことが多い
- Shi ら: STT–LCT 相対角を構造最適化で小さくする（補正より構造側）
- Rene ら: 光通信の body-pointing FF だが熱変形ではない

#### 配置変更

- TD/Femap 再解析なしで、参照ノードをパネル中央に差し替えて proxy LOS を見る手法を確立
- Case 04 などで、配置が変わっても波形は同型、振幅は変わる、という初見
- 「SUNFACE を物理ベース予測として進めてよい」という判断をメモ上で明示

## 3. いま言えること / まだ言えないこと

### 3.1 言える（ICSO の芯にできる）

1. 箱型衛星モデルでも、熱変形由来の STT–LCT 相対 LOS は数十〜数百 µrad に達しうる
2. その時変成分は、太陽指向面と反対面の温度差など少数特徴量で一次近似できる場合がある
3. Femap 真値を scan center 補正に使うと、粗捕捉指標（捕捉時間・scan-center 残差）が改善する方向に出る
4. 解析パイプライン（ケース行列 → TD → mapper → Femap → LOS → PAT）を再現可能に寄せつつある
5. JANUS 型の温度差一次モデルを、衛星バス相対 LOS + 光通信粗捕捉へ拡張するストーリーが立つ

### 3.2 まだ弱い / 要検証

1. **軽量モデル補正の PAT 性能**が、truth 補正にどこまで迫るか（within-case フィット成功 ≠ 捕捉改善の定量主張が完了）
2. **係数のケース間共通化**と、軌道ごとの校正運用（「Femap を毎回回す」前提をどこまで許すか）
3. **非熱誤差の現実味**（仮置き値 vs TLE–POD 等の実データ。熱補正の相対寄与が変わる）
4. **adaptive 層**（アブストにはあるが、評価軸を混ぜないため後回しが妥当）
5. 配置が 90° 関係のときの支配温度の一般化（More investigation needed）
6. MZ 太陽指向など、SUNFACE が説明しにくい特異ケースの扱い

### 3.3 ICSO に載せるなら優先する図・数字

メモと ToDo から抽出した候補:

- Femap LOS 角度時系列（既存）
- 感度解析比較（太陽方向 / 表面特性 / 内部発熱）
- SUNFACE: `T_sunface - T_opposite` と LOS の重ね図・係数表
- PAT: thermal LOS bias → scan center residual → acquisition time の流れ図
- 補正なし / static / sunface / truth の捕捉時間比較
- （余裕があれば）解析パイプライン図（再現性・多数ケースのアピール）

## 5. メモの取り方について

### 5.1 この細かいスタイルが効いた理由

日次 Google Doc → MD/PNG 化したメモは、単なる作業日誌以上の価値があった。

効いた具体例:

1. **光学特性未反映バグ**  
   係数一致 → 温度場一致 → パネル opt が載っていない、という因果を日を跨いで追えた
2. **mapper 混線・staging 方針**  
   GUI では見えにくい失敗モードを、後から再現手順として残せる
3. **研究デザインの分岐**  
   「バイアス支配だった理由」「時変を狙う条件」が文章で残っている
4. **JANUS 差分の言語化**  
   自分の言葉で novelty を固定できている（予稿の Related Work に直結）
5. **AI / 共同作業の引き継ぎ**  
   リポジトリにコードと結果があり、メモに意図があるので、横断レビューが研究レビューになる

「全部がリポジトリに集約されている」ことと、「思考過程がメモに残っている」ことが噛み合っている。

### 5.2 続けるべきか

**続ける。ただし粒度を二層化する。**

理由:

- 今の細かい記録は、再現性・デバッグ・主張の根拠として資産になっている
- 一方で 7/8 メモが 20 ページ超になると、ICSO 直前は「結論」と「作業ログ」が混ざり、読み戻しコストが上がる
- 研究フェーズが「仕組みを作る」から「主張を書く」に移ったため、メモの役割も変わる

### 5.3 推奨フォーマット（これからの運用）

#### A. 作業ログ（毎日〜作業単位、今のスタイルを短縮）

残すもの:

- やったこと（ケース ID、コマンド、変更ファイル）
- ハマりと解決（特に TD/Femap の罠）
- 次にやること（3 行以内）

削ってよいもの:

- GUI の全クリック逐語録（スクショ 1 枚 + 「何を確認したか」で足りることが多い）
- AI との往復の全文（結論と採用した方針だけ）

#### B. 研究メモ（週 1、または大きな結果が出た日に半ページ〜1 ページ）

必ず書く 4 点:

1. **今日言える主張**（1〜3 文）
2. **それを支える証拠**（どの case / どの図 / どの数値）
3. **反証されそうな点・未検証**
4. **ICSO に載せる図・数字への影響**（追加 / 差し替え / 不要）

この B 層が、予稿の下書きになる。A 層だけだと論文に昇華しにくい。

#### C. リポジトリ側への昇格ルール

メモに書いた内容のうち、次はリポジトリの正式ドキュメントへ移す。

- 再現手順 → `scripts/README.md` や各 `src/*/README`
- 定義（LOS の定義など） → `docs/research_notes/femap_stt_lct_los_definition.md` のような定義メモ
- 運用ルール → 今回の `260712_TD_Femap運用ルール` のような短いルール文書
- 方針の確定版 → `memo_in_repository.md` への追記、または本ファイルのような retrospective

「全部を Google Doc に残す」のではなく、**確定した知識はリポジトリの適切な場所へ昇格**する。

## 8. 結び

この 3 週間（おおよそ 6/22〜7/12）で、研究は「Femap で変形が見える」から「どの温度差が LOS を説明し、それを粗捕捉補正に使えるか」まで進んだ。スピードは速い。しかも、単なる結果の積み上げではなく、失敗（光学特性、mapper 混線、バイアス支配）を経由して主張が鋭くなっている。

細かいメモは、その鋭さを支えた。続ける価値はある。これからは同じ熱量でログを取りつつ、**週次で claim を書き出す**ことだけを足せば、リポジトリ全体が「実験装置 + 実験ノート + 論文下書き」として機能し続ける。
