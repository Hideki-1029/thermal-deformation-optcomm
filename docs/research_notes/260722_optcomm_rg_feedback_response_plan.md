## 0. まず結論

光RGのフィードバックは、研究の方向性を否定するものではなく、**論文としての主張をより堅くするための論点**に見える。特に重要なのは次の5点。

1. 軌道予測誤差の座標系・不連続性・熱との同帯域性を説明できるようにする。
2. `c_prop`, `c_pcdu` を太陽面に依存しない単一係数として置く妥当性を再検証する。
3. コンポON/OFFが軌道途中で変わる過渡状態に、今の定常bcaseモデルがどこまで使えるかを切り分ける。
4. PAT比較対象を「補正なし」だけにせず、先行研究・統計モデル・静的/校正ベースラインとの比較に広げる。
5. JANUS/STOP系の先行研究との差分を、式形ではなく「対象システム・入力・出力・目的」で説明する。

ICSO予稿では、すべてを追加解析として完璧に解くよりも、**主張の範囲を正しく置く**ことが最優先。追加解析は、論文の弱点になりやすい `c_prop/c_pcdu` と比較対象を優先する。

## 2. 論文の主張をどう直すか



### 2.1 強く言ってよいこと

- TD/Femapにより、代表衛星モデルのSTT-relative far-field LOSを熱条件ごとに算出した。
- 支配軸の熱LOSは、太陽面-反対面の温度差 `ΔT(t)` で軌道内変動をよく説明できる。
- 同一太陽面内では `a` がケース横断で安定し、共有係数として使える。
- ケース間のDCバイアス `b_case` は、太陽面と内部発熱フラグでかなり説明できる。
- 熱LOSのみを見れば、bcase feedforwardはthermal truthに近いPAT性能を出す。
- 非熱誤差込みでも、熱が大きいケースではscan center errorと捕捉時間を大きく減らせる。



### 2.2 弱めるべきこと

- 「熱と非熱を観測から分離できる」
  - 軌道予測誤差も熱と同じ軌道周期族なので、周波数分離は難しい。
  - 言い換え: 事前熱モデルに基づくfeedforwardで、熱成分だけを予測的に減らす。
- 「複数ケースへ一般化済み」
  - 今は同一基本構造・同一LOS定義・限定ケース群での横断性。
  - 言い換え: evaluated case matrixでは有効。別構造・別配置は再同定が必要。
- 「`c_prop`, `c_pcdu` は普遍係数」
  - 現状は第一版の階層モデル。
  - 言い換え: 発熱由来DCを少数係数で説明できることを示した。面依存・電力依存は追加検証。
- 「adaptiveまで完成」
  - 現状はモデル設計上の第2層候補。
  - 言い換え: `a` は事前固定候補、`b_case` や未モデル化DCがadaptive更新候補。



### 2.3 本文の一本線

```text
粗捕捉前には光フィードバックがなく、scan-center errorが捕捉時間を決める。
  ↓
熱変形LOSは大きく、軌道位相で変わるが、温度・太陽面・発熱から予測できる。
  ↓
TD/FemapでSTT-LCT far-field相対LOSをtruthとして作る。
  ↓
軌道内時変はΔT、ケース間DCは太陽面+発熱フラグ、という階層モデルへ圧縮する。
  ↓
熱のみではthermal truthに近い補正ができる。
  ↓
非熱誤差は残るが、熱由来の探索負荷は大幅に減る。
  ↓
今後は発熱過渡・面依存係数・adaptive更新・より強い比較対象を詰める。
```

## 3. 解析・実装で優先すべき対策



### A. 軌道予測誤差の説明を固める

**目的:** 次回説明や予稿で、軌道誤差グラフについて聞かれても詰まらないようにする。

現状:

- legacyの `isl_angle_x/y` は任意PAT基底で、STTボディx/yではない。
- ノルムは物理的角度量として使える。
- x/yの不連続は基底の符号反転・急回転が原因であり、物理的LOS誤差のジャンプではない。
- 7/18時点でSTTフレーム射影版を実装・整理済み。

やること:

1. PAT本文・図ではSTTフレーム射影版を標準として使う。
2. legacy x/y図は発表から落とすか、補足へ回す。
3. 軌道誤差の図には、次を必ず書く。
  - Sentinel-1 TLE vs POD
  - partner仮定
  - STT frame / LCT boresight
  - mean/p95
  - cyclic resamplingでPATへ入れていること

ICSO本文への入れ方:

- 「非熱誤差のうち軌道予測誤差は Sentinel-1 TLE vs POD を用い、LCT boresight横断面のSTTフレーム角度へ変換した」と短く書く。
- 詳細な3グラフは予稿には入れず、誤差バジェット表か1文で十分。



### B. `c_prop/c_pcdu` の面依存・交互作用チェック

**目的:** 「太陽面で支配軸が変わるのに、発熱係数が一定でよいのか？」に答える。

現状モデル:

```text
b_case ≈ b0(sun_face) + c_prop I_prop + c_pcdu I_pcdu
```

懸念:

- PROP/PCDUの取付位置と太陽面の関係で、発熱の効き方は変わるはず。
- 現行係数はMY/PY中心の発熱スクリーニングに強く依存している可能性。
- MX/PXでは発熱効果が小さいため、共通係数に入れるべきでないかもしれない。

追加比較案:


| モデル          | 式                                             | 目的            |
| ------------ | --------------------------------------------- | ------------- |
| 現行           | `b0(sun)+c_prop I_prop+c_pcdu I_pcdu`         | 最小モデル         |
| heat faces限定 | MY/PYだけ発熱係数有効                                 | 現行実装の明示       |
| sun×heat     | `b0(sun)+c_prop(sun)I_prop+c_pcdu(sun)I_pcdu` | 面依存の必要性チェック   |
| axis×heat    | x/y支配軸ごとに係数                                   | データ不足を抑えた交互作用 |
| power比例      | `c_prop P_prop + c_pcdu P_pcdu`               | ON/OFFから連続電力へ |


判断基準:

- LOO `b` RMSEが改善するか。
- 係数が物理的に解釈できる符号・大きさか。
- データ数に対して過剰自由度でないか。
- PAT結果でstatic/bcaseの順位が安定するか。

ICSOへの反映:

- 追加解析が間に合うなら、Discussionに「sun×heatを試したがLOO改善は限定的/または改善したため採用」と書く。
- 間に合わない場合は、Limitationsに「current Level-2 uses a compact heat-flag model; face-dependent heat coefficients are under evaluation」と明記。



### C. コンポON/OFF過渡

**目的:** 高嶋さんの「途中でコンポON/OFFした場合は？」への答えを作る。

現状:

- モデルは定常発熱ケースからfitしている。
- `I_prop`, `I_pcdu` はケース全体のON/OFFフラグ。
- 軌道途中でONになる過渡温度応答はまだ見ていない。

考え方:

1. 瞬時に `b_case` が切り替わるわけではない。
2. 発熱ON後、局所温度と構体温度場は熱時定数に従って変化する。
3. 現行モデルは「十分定常化した発熱状態」または「発熱モードが軌道をまたいで固定」の近似。
4. 過渡に対応するには、フラグではなく発熱履歴または局所温度状態が必要。

追加解析案:

- TDで1ケースだけ、軌道途中PROP/PCDU ONの過渡ケースを作る。
- `I(t)` をステップ入力にしたときのLOS応答を見る。
- 既存bcaseモデルで補正した残差を確認する。
- 簡易モデル候補:
  - `b_case(t)` を一次遅れで更新
  - `I_prop`ではなくPROP近傍温度の低周波成分をLevel-2入力にする
  - adaptive層で過渡DCを吸収する

ICSOへの反映:

- 本文では「本稿のbcaseモデルは定常運用モードのfeedforwardを対象とする」と明記。
- 過渡ON/OFFは今後課題。
- adaptive層の動機として使うとよい。



### D. 比較対象を強くする

**目的:** 「補正なし相手では弱い」という指摘に対応する。

現状比較:

- no correction
- static bias
- bcase
- thermal truth
- nonthermal込み no / bcase

問題:

- no correction は弱すぎる。
- static bias は最低限の工学的baselineだが、先行研究相当・統計モデル相当とは言いにくい。
- thermal truth は上界であり実装可能baselineではない。

比較候補:


| baseline                | 内容                        | 実装負荷 | 論文での役割             |
| ----------------------- | ------------------------- | ---- | ------------------ |
| static bias             | 学習区間平均を引く                 | 済    | 最低限の校正             |
| Fourier                 | 軌道周期の経験的時系列fit            | 既存あり | 時系列経験モデル           |
| temperature Ridge       | 温度特徴量をまとめて回帰              | 既存あり | black-box寄り温度モデル   |
| sunface_deltaT only     | `b_emp + aΔT` within-case | 既存あり | Level-2なしのoracle寄り |
| ML all-error            | 熱+非熱をまとめて予測               | 未実装  | 「全部学習」との対比。ただし危険   |
| JANUS-like proportional | 原点通過 `aΔT`                | 容易   | 先行式形との対比           |


ICSOでの現実的最小セット:

1. no correction
2. static bias
3. JANUS-like / deltaT proportional
4. hierarchical bcase
5. thermal truth upper bound

可能ならFourierも入れる。

注意:

- 比較条件は同じ非熱誤差・同じscan条件で揃える。
- thermal truthは「上界」と明記し、提案手法扱いしない。
- ML all-errorは、データ数が少ないと過学習比較になりやすい。今すぐICSO主図に入れるかは慎重。



### E. JANUS/STOPとの差分を整理する

**目的:** 「先行研究と近すぎる」不安を、論文上の正しい位置づけに変える。

近い点:

- STOP解析系の流れ:
  - ESATAN/Thermal Desktop
  - NASTRAN/Femap
  - optical/LOS evaluation
- 温度差とLOSの一次関係
- 地上解析だけでもSPIE論文として成立しうること

違う点:


| JANUS/STOP             | 本研究                              |
| ---------------------- | -------------------------------- |
| 単一光学機器内部               | 衛星バス上のSTTとLCTという別機器間             |
| 科学画像・ジオロケーション補正        | 光通信粗捕捉のscan center補正             |
| 限定ミッション軌道・熱ケース         | 太陽面・発熱・被覆・軌道条件を振ったケース横断          |
| 温度差比例が主                | `aΔT` + ケースDC `b_case` の階層モデル    |
| calibrationでバイアスを扱う可能性 | 発熱ON/OFF等でDCを予測し、将来adaptive更新へ接続 |
| LOS精度評価                | PAT捕捉時間・成功率への接続                  |


論文での書き方:

- 「JANUS型の温度差-LOS関係を参考にしつつ」と明示してよい。
- 「式形の新規性」は主張しない。
- 「システム階層と評価目的が違う」と書く。
- STOP解析の2019論文は必ず読み、関連研究へ追加する。

## 4. ICSO予稿への即時反映案



### 4.1 Introduction

入れるべき文脈:

- 粗捕捉前は光フィードバックが使えない。
- 初期指向誤差には熱と非熱が混在する。
- 軌道予測誤差なども同じ低周波帯域にあり、観測だけで熱を分離するのは難しい。
- だから、事前熱モデルによるfeedforwardに価値がある。

避ける:

- 「熱ひずみを観測から分離する」
- 「adaptiveで全誤差を補正する」



### 4.2 Related Work

必ず入れる:

- JANUS温度差LOS
- STOP解析論文
- 熱変形LOS補正のEarth observation系
- 光通信PAT/pointing feedforward

差分の書き方:

```text
本研究は、温度差とLOSの一次関係そのものではなく、
衛星バス上のSTT-LCT相対LOSを対象に、
ケース間DCを運用状態で階層化し、
粗捕捉性能へ接続する点に焦点を置く。
```



### 4.3 Model

追記すべき注意:

- `a` は太陽面ごとの共有係数として安定。
- `b_case` は運用状態で変わるため、Level-2またはadaptive対象。
- 現行 `c_prop/c_pcdu` は定常発熱状態の第一版モデル。
- 面依存や発熱過渡は今後課題。



### 4.4 PAT Evaluation

追記すべき注意:

- 熱のみ評価と非熱込み評価を明確に分ける。
- 非熱誤差の中で軌道予測誤差が支配的。
- 軌道予測誤差はSTT frameへ射影して加える。
- 捕捉成功率の定義:
  - 最大スキャン時間/範囲内に検出半径へ入れば成功
  - 超えた場合失敗
- no correctionだけでなくstatic/JANUS-like/Fourier等と比較する。



### 4.5 Discussion

書くべき限界:

- 同一衛星モデル内の評価であり、別構造は再同定が必要。
- HOT/Black/半電力/過渡発熱はLevel-2拡張候補。
- 非熱誤差と熱誤差は周波数帯域が重なる。
- adaptiveは未実装であり、主結果はfeedforward。

## 7. 現時点の推奨方針

ICSOに向けた最短で堅い方針は以下。

1. **予稿の主軸は現行bcase feedforwardで維持する。**
  - 研究の芯はすでに強い。
  - LOS予測とPAT接続が一気通貫で示せている。
2. **ただし新規性の表現をJANUS/STOPとの差分へ寄せる。**
  - 式形ではなく、STT-LCT相対LOS、ケースDC階層化、粗捕捉性能接続を押す。
3. `c_prop/c_pcdu` **の交互作用チェックだけは優先して行う。**
  - 先輩FBで一番技術的に刺さっている。
  - 結果が現行モデル支持でも、モデル変更でも、論文が強くなる。
4. **PAT比較対象を少しだけ強くする。**
  - no/static/bcase/truthに加え、JANUS-like or Fourierを入れる。
