## 1. いまの評価が熱について甘い理由

非熱は Sentinel-1 TLE vs POD などを真値に足しているので、軌道側はリアル寄り。

熱は:

```text
真値 LOS     = Femap（ケース X）
θ_ff の a, b = 同じ Femap ファミリーの別ケース（LOO でも物理は同一）
ΔT(t)        = ほぼそのケースの真のパネル温度
```

LOO は「その1本の時系列」を外すだけで、メッシュ・材料・ΔT 定義・軌道族は共有。FF 後の熱残り数 µrad は **同一シミュレータ内の近似誤差**。

現実でありうる差を、**地上解析で合わせられるもの**と **合わせきれないもの**に分ける。

地上解析の条件を軌道に合わせれば（かなり）済む:

| ずれ | 今の sim | コメント |
|------|----------|----------|
| HOT vs COLD | 主評価は近い条件 | **解析軌道を合わせればよい。** Adaptive の必須動機ではない |
| 既知の発熱モード | Level-2 に載りやすい | 発熱ケースを回せば表に入る |
| 設計どおりの被覆 | 学習と真値が同じ系統 | 被覆ケースを回せばよい |

地上解析では本質的に残る（打上げ・実装のあと）:

| ずれ | 今の sim |
|------|----------|
| 打上げ衝撃などによるアライメント（STT–LCT 定数バイアス） | なし |
| 剛性・境界条件の実機差（感度 `a` やスイング） | なし |
| 被覆の実機ばらつき・劣化 | なし（実測 ΔT なら主効果は ΔT 側。残るのは波形の床） |
| 軌道上 ΔT センサ誤差 | ほぼ真温度 |

HOT/COLD を「未知ずれ」の例に使うのは弱い。季節・β角が分かれば対応する TD ケースを事前に回せる。case10 の `b` 数 µrad ずれは、Level-2 に HOT フラグが無い／COLD 表を流用したときの話。

「Adaptive `b` の余地がない」は、手法が強いことに加えて **熱モデル誤差をほとんど入れてない**。非熱を足しても軌道の話であり、熱 Adaptive の動機（テーブルが真値とずれる）にはならない。

## 2. ずれの種類と、どの層が吸うか

```text
θ_ff = b_case + a·ΔT     ← 事前熱（Femap 由来テーブル）
     + c0 または δb       ← 残差 DC
     + Σ sin/cos(kφ)     ← 残差の周期（260813）
```

| ずれ | `c0` / `δb` | 残差 Fourier AC | `b_case` 更新 |
|------|-------------|-----------------|---------------|
| 打上げ後アライメント（STT 枠の定数） | **本命**。mode 非依存 DC | 不要 | **やらない**（熱表が汚れる） |
| 剛性 → `a` が変わる | 平均だけ | 同じ面・同じ軌道ならスイングも吸える | 温度構造をテーブルに残したいとき |
| 未知発熱で **面依存 DC** | その mode の `δb` でも可 | DC は `c0` | 熱として持ちたいなら `b_case` |
| 被覆（α/ε） | ほぼ効かない（既存 11/12 は `b` ほぼ不変） | **床上げの本命**（Black で ~13 µrad） | ほぼ効かない |
| 軌道の AC | 不可 | 本命（260813） | 不可 |

アライメント問題があるから Adaptive `b` が要る、とは限らない。定数バイアスの本命は後段 DC。`b` 更新が残るのは、ずれが **温度・面・発熱の構造**を持ち、モードをまたいで熱テーブルとして持っていたいとき。

## 3. シミュレーションで熱誤差を入れる案（未実装）

真値生成と係数学習を同じファミリーにしない。

| 入れ方 | 何を見るか |
|--------|------------|
| 真値 LOS に定数アライメント（STT x/y）を足す | **本命の「地上解析ではどうしようもない」ずれ。** `c0`/`δb` で吸えるか |
| 真値の熱スイングをスケール（疑似剛性） | `c0` だけでは不足、Fourier AC vs `a` 更新 |
| ΔT にセンサノイズ | FF の入力誤差 |
| （参考）学習 COLD・真値 HOT | 条件不一致のデモにはなるが、解析を合わせれば消える。Adaptive 必須動機ではない |

ICSO 主結果（階層 FF）は今の同一機械評価のままでよい。このノートの実験は Adaptive / 後段の動機用。

### 3.1 実装するか、Adaptive `b_case` に効くか（2026-08-13）

4つは「地上では埋めきれない熱まわりのずれ」としては全部本物。ただし **全部入れると `b_case` 更新が効く、ではない。** 定数 DC は `δb`/`c0`（目標B）で足り、`b_case`（目標A）が意味を持つのはずれが **面・発熱の熱テーブル構造**を持つときだけ。

| ずれ | 実装？ | `δb` / `c0` | 遅い `b_case` | 備考 |
|------|--------|-------------|---------------|------|
| アライメント（真値 LOS に定数） | **先にやる。安い・本命** | **効く** | 数値上は吸えるが **やってはいけない**（熱表が汚れる） | 目標Bのデモ。目標Aのデモに使わない |
| 剛性（熱スイングをスケール） | **やる。`δb` の限界を見せる** | 平均だけ | 平均だけ。スイングは残る | 本命は `a` 更新か Fourier AC。`b_case` だけでは case13 と同じ薄さ |
| 被覆ばらつき・劣化 | 残差床のデモなら可。**`b_case` 用ではない** | ほぼ効かない | ほぼ効かない | 実測 ΔT なら `a` もほぼ同じ（case11 `a=28.7`）。効くのは 2 点 ΔT に入りきらない波形 → Fourier |
| ΔT センサ | バイアスは後で可。ノイズは優先低い | 定数バイアスなら効く | ほぼ効かない | ノイズは平均で消える。ゲイン誤差は剛性と同じ形 |

結論:

- **4つとも「現実の残差」としては実装する価値がある**（階層 FF の同一機械評価を甘くしないため）。
- 4つの「地上で埋めきれないずれ」を足しても、**遅い `b_case` 更新が PAT を動かす線は薄い**（§3.2）。
- 実装するなら目標は `b_case` 効果ではなく、層の役割確認: (1) アライメント → `δb` (2) スイングスケール → Fourier / `a` (3) 被覆は任意（床） (4) ΔT バイアスはおまけ。

### 3.2 遅い `b_case` Adaptive は薄いか（2026-08-13）

**薄い、という判断でよい。** 熱誤差を足しても、多くは `δb`（DC）か Fourier/`a`（AC）に落ち、`b_case` テーブルへ戻す理由が残らない。

| ずれ | なぜ `b_case` に来ないか |
|------|--------------------------|
| アライメント | mode 非依存 DC。熱表を汚す |
| 剛性 | 主に `a·ΔT` のゲイン。切片は平均だけ |
| 被覆 | 実測 ΔT なら `a` も `b` もほぼ不変。波形の床 |
| センサ | バイアスは `δb`、ノイズは平均 |
| HOT/COLD | 解析条件を合わせればよい |
| 既知の発熱 ON/OFF | Level-2 に載せれば、軌道上フラグで足りる |

`b_case` 更新が残るのは狭い:

- Level-2 が外れている（`c_prop` が実機と違う、表に無い発熱）**かつ** それを熱テーブルとして持ちたい
- 寿命で発熱 DC がゆっくり変わるのを、`δb` に置きっぱなしにせず表へ昇格したい

どちらも **捕捉時間（目標B）ではなくテーブルの身分（目標A）**。PAT を動かす Adaptive は `δb` と残差 Fourier で足りる、が今の整理。

被覆の物理（`a` に効くか）:

```text
α/ε がずれる → 温度場 T(x) が変わる → 観測 ΔT の振幅が変わる
LOS ≈ a_struct · ΔT_meas + 残余
```

`a` は構体の剛性・CTE・配置（µrad/°C）なので、**一様な光学特性のスケールだけでは `a` は動かない。** 軌道上でパネル温度を測って FF するなら、被覆ずれの主効果はすでに ΔT に入る。残るのは「2 点 ΔT が温度場の形を取りこぼす」分で、それは `a` の再同定というより残差波形（Black で RMSE 床 ~13 µrad）。カタログ α/ε から ΔT を予測する運用なら、被覆誤差は誤った ΔT に見え、`a·ΔT` のゲイン誤差と区別しにくい。
