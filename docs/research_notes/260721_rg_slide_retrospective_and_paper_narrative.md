## 0. 結論

AI初稿は、研究に含めるべき論点と全体の章立てはおおむね捉えていた。一方で、**研究内容を調べた側の理解順に情報を圧縮し、聞き手・読者が理解する順番を十分に設計していなかった**。

特に問題だったのは、光通信の専門家であることを、今回新たに定義したモデル、記号、評価条件まで既知であると誤解したことである。そのため、初出の用語や式が説明なしに現れ、観察結果より先にモデル解釈を述べ、解析の入力・出力の順番も前後した。

予稿では、情報量を減らすことではなく、次の順序を守ることが重要である。

> 運用上の問題 → 補正対象の限定 → 物理的な因果 → 解析による観察 → モデル化の必要性 → 記号と式 → 検証方法 → 結果 → PAT上の意味 → 限界と次の課題

## 1. スライド作成の振り返り

### 1.1 初稿で意図していたこと

初稿では、30–40分の専門家向け発表として、次を狙っていた。

- 今回の成果と議論点を早い段階で提示する
- 熱構造解析、軽量LOSモデル、PAT評価を一気通貫で示す
- 各スライドのタイトルだけでも主張が追えるようにする
- シミュレーション条件を省略せず、議論に必要な材料を揃える
- 数式と定量結果を示し、前回の「構想」から進んだことを明確にする

この方針自体は維持してよい。問題は、結論先行と説明省略を混同し、「掲載した情報量」を完成度の代わりにしてしまったことである。

### 1.2 「研究を知っている」の解釈が広すぎた

光RGの聞き手が知っているのは、光通信、PAT、研究の大目的である。一方、次の語は今回の解析・モデルで初めて定義するものであり、専門家に対しても説明が必要だった。

- `far_field_los` / `stt_relative_los`
- 太陽指向面–反対面温度差 `ΔT`
- 共有熱感度 `a`
- ケース依存DC `b_case`
- Level 1 / Level 2
- leave-one-out（LOO）評価
- thermal-truth correction

初稿では、これらを一般用語のように置いてしまった。専門家向け資料で省略できるのは分野の基礎説明であり、**本研究固有の定義ではない**。

### 1.3 解析の説明順が因果関係の順になっていなかった

初稿の熱構造解析パートは、おおむね次の順だった。

```text
衛星モデル
→ LOS定義
→ 軌道・熱条件
→ 構造条件
→ 発熱条件
→ ケース一覧
```

しかし、読者が解析を理解する自然な順番は次である。

```text
衛星モデルと機器配置
→ Thermal Desktopへの入力（軌道・姿勢・表面特性・発熱）
→ 温度場
→ Femapへの入力（温度場・材料・拘束）
→ 変位・回転
→ STTとLCTの回転からLOS真値を定義
→ 条件を横断するケース設計
```

v3ではTDとFemapの役割を分け、内部発熱をTDの入力として説明した後にLOS真値を定義した。この修正により、「どの計算から、そのLOS時系列が得られたのか」を順に追えるようになった。

### 1.4 観察より先にモデルの解釈を置いていた

初稿では、熱構造解析の途中で次の趣旨を述べていた。

> 発熱の主効果はΔTへ、ΔTに入りきらない残差DCは `b_case` へ入る。

この段階では、まだ次を説明していなかった。

- なぜ温度差 `ΔT` を見るのか
- DCがどの時間平均・どのケース差を指すのか
- 軌道内変動とケース間差を分ける必要がある理由
- 発熱が両方へ影響するという観察結果

したがって、モデル構築後の解釈を、観察結果より前に提示していた。正しい展開は次である。

1. 温度場と熱LOSが同じ軌道周期で変化することを示す。
2. 太陽指向面により支配軸と符号が系統的に変わることを示す。
3. 同一ケース内の時変成分と、条件間で変わる平均値があることを示す。
4. この観察を表すため、`a ΔT` と `b_case` に分ける。
5. その後で初めて式を提示する。

### 1.5 結論タイトルを断定の道具にしてしまった

初稿では、タイトルを結論形にすることを優先するあまり、その場の根拠より先に進んだ表現があった。

- 「簡略shellモデルを高忠実度参照とする」
- 「新規性は式形ではなく、衛星バス相対LOSと粗捕捉への接続にある」
- 「`a` は事前同定、`b_case` は軌道上更新する価値が高い」

「簡略」と「高忠実度」は比較対象を明示しなければ矛盾して見える。また、新規性や運用方針は、解析結果と先行研究を示してから述べるべきである。

結論先行のタイトルは有効だが、次の条件を満たす必要がある。

- 本文と図だけで、そのタイトルの結論をその場で支持できる
- 比較対象と適用範囲が分かる
- 後の節で初めて定義する語を使わない

### 1.6 ラベルを置くことと説明することを混同した

初稿の `High-fidelity reference`、`Operational layer`、`Quantify / Predict / Improve` などは、構成を整理するラベルではあったが、研究上の意味を十分に説明していなかった。

v3では、これらを「地上でのモデル構築」「軌道上でのモデル運用および補正」とし、さらに次を文章で明示した。

- TD/Femapは地上での教師データ生成と妥当性評価に用いる
- 軌道上では少数温度センサと運用情報を軽量モデルへ入力する
- 予測した熱LOSをscan centerから差し引く
- 捕捉後残差を将来のモデル更新に利用する

予稿でも、抽象的な層名だけで済ませず、各層の入力、処理、出力、実行場所を書く。

### 1.7 用語、単位、主語、比較対象が不足していた

初稿の「ケースDC」「共有感度」「同帯域」「上界」「性能を支配する」などは、短いが意味が一意ではなかった。

予稿では、少なくとも初出時に次まで書く。

- ケースDC: 各ケースの評価区間における熱LOSの平均的オフセット
- 共有感度: 同一太陽指向面の複数ケースで共通に用いる `ΔT`–LOS傾き
- 同帯域: 熱LOSと軌道予測誤差がともに軌道周期およびその近傍の周波数成分を持つこと
- 理想上界: 熱LOS真値を既知として完全に差し引いた場合のPAT性能
- 支配する: 補正後の残差分散または捕捉時間への寄与が他成分より大きいこと

日本語と英語は、慣用的な専門語または式中の変数名のみ英語を残し、単なる見出し上の装飾として混在させない。

## 2. 予稿につなげる研究の説明順

以下は、今回の研究を読者に理解させるための推奨順序である。これは単なる章立てではなく、**各概念を読者へ渡す順番**を示す。

### 2.1 運用上の問題から始める

最初に説明するのは熱モデルではなく、粗捕捉時の問題である。

1. 光リンク確立前は光学フィードバックを利用できない。
2. 衛星は姿勢、軌道、アライメント、熱変形などを含む初期指向不確定領域を走査する。
3. scan-center errorが大きいと、探索領域と捕捉時間が増える。
4. このうち熱変形は、日照、軌道位相、表面特性、機器発熱と関係するため、事前予測できる可能性がある。

ここではまだ `a`、`b_case`、Level 1/2を出さない。

### 2.2 補正対象を限定する

次に、本研究が何をしないかを明確にする。

> 本研究はすべての指向誤差を除去するものではなく、初期指向誤差のうち予測可能な熱成分をfeedforwardで低減する。

この限定を先に置くことで、後に非熱誤差が残る結果を示しても、研究の失敗ではなく設計どおりと説明できる。

### 2.3 熱からscan-center errorまでの物理的な鎖を示す

```text
日照・食／内部発熱
→ 衛星各面の温度場
→ 差動熱膨張と構体の曲げ・ねじれ
→ STTとLCTの相対光軸回転
→ 粗捕捉開始時のscan-center error
```

この段階では詳細式よりも、なぜ温度情報がLOS予測に使えそうなのかを説明する。

### 2.4 数値解析の入力・処理・出力を順番に定義する

Thermal DesktopとFemapをソフト名として紹介するだけでなく、役割を分けて書く。

1. 箱型衛星モデルとSTT/LCT・発熱機器の配置を定義する。
2. 軌道、姿勢、表面熱光学特性、機器発熱をTDへ入力する。
3. TDから時系列温度場を得る。
4. 温度場、材料特性、拘束条件をFemapへ入力する。
5. STT/LCT基準面の並進・回転を得る。
6. STTを姿勢基準とし、LCT光軸との相対回転を遠方通信用LOS誤差として定義する。

LOSの式は6番目で初めて出す。式の前に、並進ではなく相対回転を採用する物理的理由を書く。

### 2.5 ケース設計を説明してから代表結果を示す

結果の前に、何を変え、何を固定したかを書く。

- 変化させる条件: 太陽指向面、内部発熱、表面特性、軌道・熱環境
- 固定する条件: 基本構造、STT/LCT配置、材料、LOS定義
- 対象範囲: 同一基本構造内の条件横断性
- 対象外: 別衛星構造への一般化、飛行実証、MZ太陽指向など

その後、代表ケースとケース横断結果から次の観察を順に示す。

1. 熱LOSは温度場と同じ軌道周期で変化する。
2. 太陽指向面により支配軸と符号が変わる。
3. 同一太陽指向面では、温度差に対する傾きが比較的安定する。
4. 発熱、被覆、軌道条件により平均オフセットが変わる。

### 2.6 観察結果から軽量モデルを導く

モデルを先に宣言せず、上の観察を受けて必要性を述べる。

> 軌道上ではTD/Femapを実行できないため、少数温度センサと既知の運用情報から熱LOSを直接予測する軽量モデルが必要である。解析結果は、軌道内の時変成分と、条件間で変わる平均成分を分けて扱えることを示唆した。

この文章の後で、まず概念を言葉で定義する。

- 軌道内時変成分: 太陽指向面と反対面の温度差に伴って変化する成分
- ケース間DC成分: 発熱モード、被覆、軌道条件などによりケースごとに変わる平均オフセット

その後で式を出す。

```text
Level 1:
θ_dom(t) = b_case + a_s ΔT(t) + ε(t)

Level 2:
b_case = b0,s + c_PROP I_PROP + c_PCDU I_PCDU + η_case
```

式の直後に、全記号を文章で説明する。

- `θ_dom(t)`: 太陽指向面から定まる支配軸の熱LOS
- `ΔT(t)`: 太陽指向面中心と反対面中心の温度差
- `a_s`: 太陽指向面 `s` ごとに共有する熱感度
- `b_case`: 各解析ケースの平均的なLOSオフセット
- `b0,s`: 太陽指向面ごとの基準オフセット
- `I_PROP`, `I_PCDU`: 各機器の発熱モードを示す変数
- `ε(t)`, `η_case`: 各階層でモデル化されない残差

### 2.7 学習方法と評価方法を結果より前に書く

モデルの数値結果を出す前に、データの使い方を説明する。

1. 各ケース内で `a` と `b_case` の候補を推定する。
2. 同一太陽指向面の複数ケースから共有感度 `a_s` を定める。
3. ケース間の `b_case` を太陽指向面と発熱モードで説明する。
4. 学習に使ったケースへの適合と、leave-one-outで除外したケースへの予測を分けて評価する。
5. 生LOSの大きさと予測残差には異なる統計量を用いる場合、その違いを明記する。

結果は次の順で示す。

- 共有感度のケース横断安定性
- Level 2の `b_case` 再現性
- 代表時系列における真値と予測値
- 全ケースのtest/LOO誤差
- 難しいケースと失敗理由

### 2.8 PAT評価では、式より先に信号の流れを説明する

最初に文章とブロック図で次を示す。

```text
真の熱LOS
− 軽量モデルが予測した熱LOS
+ 軌道・姿勢・アライメント等の非熱誤差
= スキャン中心から見た残差
→ 粗捕捉シミュレーション
→ 捕捉成功率・捕捉時間
```

その後で残差を定義する。

```text
e_scan(t) = e_nonthermal(t)
          + θ_thermal,true(t)
          − θ_hat_thermal(t)
```

続いて、スキャン範囲、step、検出半径、dwell、最大点数、成功判定、平均捕捉時間の母集団を説明する。結果より前に、簡略化した点も明記する。

- 点間移動・settlingを省略
- 走査中の対象運動を簡略化
- 各走査点を独立な捕捉機会として扱う
- 受光強度の確率変動を扱わない

### 2.9 熱のみの結果と非熱込みの結果を役割分担させる

結果は混ぜずに二段階で示す。

1. **熱のみ:** 軽量モデルが熱成分をどこまで除去できるかを確認するモデル能力評価
2. **非熱込み:** 実際の粗捕捉性能にどの程度寄与するかを確認する主評価

thermal-truth correctionは、熱LOS真値が既知の場合の理想比較であり、実装可能な提案手法として書かない。非熱込みの結果では、熱補正後にどの誤差成分が残るかまで解釈する。

### 2.10 Adaptiveは結果から必要性を導く

Adaptiveを研究構想として先に大きく掲げるのではなく、結果から更新対象を絞る。

- 共有感度 `a_s` がケース横断で安定するなら、地上解析または熱真空試験で事前固定する候補となる。
- `b_case` が発熱・被覆・軌道条件で変わるなら、運用テーブルまたは軌道上残差による更新候補となる。
- 熱LOSと軌道予測誤差が同じ軌道周期帯を持つなら、単純な低周波抽出だけでは分離できない。
- したがって、捕捉後残差をすべて熱として吸収せず、運用モード、軌道誤差の事前値、複数パス平均などの制約が必要になる。

この順序なら、「なぜ `a` ではなく主にDCを更新するのか」が解析結果から自然につながる。

### 2.11 ContributionとLimitationは最後に対応させる

主張と限界は対で書く。

| 本研究で示すこと | 対応する限界 |
|---|---|
| 同一基本構造の複数熱条件でSTT–LCT相対LOSを算出 | 実機構造・別衛星への一般化は未評価 |
| 太陽面温度差による支配軸LOSの軽量予測 | 非支配軸・MZ太陽指向などは対象外 |
| 発熱モードを用いたケースDCの階層化 | 連続発熱量、被覆、HOT条件の完全な一般化は未完 |
| 非熱誤差を含むPAT改善 | 誤差バジェットとscan dynamicsは簡略化を含む |
| Adaptive更新対象の候補を整理 | 軌道上推定器の実装・飛行実証は未実施 |

## 3. 予稿の章ごとの役割

既存の `260715_icso_paper_outline.md` を、読者へ情報を渡す順番の観点から次のように運用する。

### 3.1 Introduction

順序:

1. 粗捕捉とscan-center errorの運用上の問題
2. 熱変形が予測可能な誤差成分になりうる理由
3. 既存研究が扱った範囲
4. 未解決点: 衛星バス上のSTT–LCT相対LOSからPAT性能までの接続
5. 本研究の目的と貢献

Introductionで階層モデルの詳細式は出さない。貢献には「何を示すか」を書き、結果の数値や実装詳細を詰め込みすぎない。

### 3.2 Problem formulation / LOS definition

順序:

1. 補正対象は熱成分のみ
2. STTを姿勢基準、LCTを送信光軸とする
3. 遠方通信では相対光軸回転を採用する
4. scan-center補正と残差を定義する

ここで研究全体の入出力を固定し、後続節でLOSという語の意味が変わらないようにする。

### 3.3 Thermo-structural analysis

順序:

1. 衛星モデル
2. TD入力と温度場
3. Femap入力と変形
4. LOSへの変換
5. ケース設計
6. 代表結果
7. モデル設計につながる観察

ソフトの操作説明ではなく、各段階が次段階へ渡す物理量を中心に書く。

### 3.4 Lightweight model

順序:

1. オンボード軽量化の要求
2. 解析結果から得た二種類の変動
3. モデルの概念
4. 記号定義
5. Level 1式
6. Level 2式
7. パラメータ同定とtest/LOO設計
8. 結果と限界

「式が単純であること」ではなく、「どの観察をどの項が表すか」を中心に説明する。

### 3.5 PAT evaluation

順序:

1. 予測LOSをscan centerへ使う方法
2. 熱・非熱誤差の合成
3. 粗捕捉モデルと仮定
4. 比較条件
5. 評価指標
6. 熱のみの能力評価
7. 非熱込みの主評価
8. ケース依存性と支配要因

捕捉時間の数字を、スキャン条件や成功判定より先に出さない。

### 3.6 Discussion / Conclusion

順序:

1. どの結果がどの研究問いに答えたか
2. 先行研究との差分
3. 運用上の意味
4. Adaptiveへの帰結
5. 限界
6. 今後の検証

Discussionで初めて重要な定義や条件を追加しない。本文中で示した事実の意味を議論する場所とする。

## 4. 段落と数式の書き方

### 4.1 技術段落の基本形

各段落は、可能な限り次の順で書く。

1. **Topic sentence:** この段落で言いたいこと
2. **Context / definition:** 対象、条件、用語の定義
3. **Method or evidence:** 何を計算・比較したか
4. **Result:** 数値または観察事実
5. **Interpretation:** なぜそうなったか、何を意味するか
6. **Boundary / transition:** 適用範囲または次段落への接続

結果と解釈を同じ文に圧縮しすぎない。例えば、「相関したためモデル化できる」ではなく、「相関を観察した」「この観察から温度差を説明変数に選んだ」と分ける。

### 4.2 数式を出すときの基本形

数式は次の三点セットで導入する。

1. 式の前: 何を表すための式かを日本語で書く
2. 式
3. 式の後: 全記号、符号規約、単位、既知量・推定量を説明する

悪い導入:

> `θ = b + aΔT`

良い導入:

> 各ケースの支配軸熱LOSを、ケース内で変動する面間温度差の寄与と、ケースごとの平均オフセットに分ける。時刻 `t` における熱LOSを次式で表す。
>
> `θ_dom(t) = b_case + a_s ΔT(t) + ε(t)`
>
> ここで、`θ_dom` は太陽指向面から決まる支配軸の熱LOS、`ΔT` は太陽指向面と反対面の中心温度差、`a_s` は同一太陽指向面のケース間で共有する感度、`b_case` はケースごとの平均オフセットである。

### 4.3 数値を書くときの基本形

数値には必ず次を付ける。

- 対象ケースまたは集計対象
- 学習データかtest/LOOか
- 指標の定義（RMSE、mean、median、peak-to-peakなど）
- 単位
- 比較対象

例えば「残差5.5 µrad」だけでは不十分であり、「21ケースのleave-one-out評価における予測残差RMSEのケース平均」のように書く。

## 5. 初出語と記号の管理

予稿作成時には、少なくとも次の表を内部チェック用に持つ。

| 用語・記号 | 初出前に必要な説明 |
|---|---|
| scan center | 粗捕捉走査の中心と、誤差が捕捉時間へ効く理由 |
| thermal LOS | STT基準で見たLCT光軸の相対回転であること |
| far-field LOS | centerline tiltを含めない理由 |
| dominant axis | 太陽指向面によりX/Yを選ぶ規則 |
| `ΔT` | どの面のどの位置の温度差か |
| `a_s` | 同一太陽指向面で共有する傾き、単位 |
| `b_case` | どの区間の平均的オフセットか |
| Level 1 / Level 2 | 軌道内時変とケース間差の階層であること |
| LOO | 何を一つ除外し、何を学習・予測するか |
| thermal truth | TD/Femapから得た参照熱LOSであること |
| nonthermal error | 軌道、姿勢、アライメント、ドリフトの内訳 |
| adaptive update | 何を観測し、どのパラメータを更新するか |

初出チェックは、単語検索だけでなく、**その直前までを読んだ読者が定義を知っているか**で判断する。

## 6. 避けるべき展開

今回の初稿で生じた失敗を、予稿の禁止パターンとして残す。

- IntroductionやOverviewで研究固有の式を説明なく出す
- TD/Femapの入力・出力を説明する前にLOS真値だけを定義する
- 観察結果を示す前に `a`、`b_case`、Level 1/2を既定のものとして扱う
- モデル評価方法を説明する前にRMSEを示す
- PAT条件を説明する前に捕捉時間の改善率を示す
- thermal truthを実装可能な提案手法と同列に書く
- 熱のみの理想結果を主たるシステム性能として強調する
- 「高忠実度」「安定」「大幅」「支配的」など、比較対象のない形容を使う
- 新規性を防御的な標語だけで述べ、先行研究との対象・入力・出力の差を書かない
- 発表者ノートや口頭説明がなければ意味が決まらない文章を本文に置く

## 7. 予稿ドラフトのレビュー項目

### 7.1 読者の理解順

- [ ] 各節の最初に、その節が必要な理由がある
- [ ] 初出の研究固有語を、その場で説明している
- [ ] 入力 → 処理 → 出力の順になっている
- [ ] 観察 → 解釈 → モデル化の順になっている
- [ ] 評価方法 → 結果 → 解釈の順になっている
- [ ] 後の節で定義する概念を前の節で使っていない

### 7.2 数式・数値

- [ ] 式の前に目的、式の後に記号定義がある
- [ ] 座標系、符号、単位が分かる
- [ ] 学習とtest/LOOが区別されている
- [ ] 集計対象と統計量が分かる
- [ ] 比較条件が同じ前提に立っている

### 7.3 主張の境界

- [ ] 熱成分のみを補正する研究であることが一貫している
- [ ] 同一基本構造内の条件横断性と、別構造への一般化を混同していない
- [ ] 数値解析結果と飛行実証を混同していない
- [ ] Adaptiveの構想・候補と、実装済み評価を区別している
- [ ] ContributionとLimitationが対応している

### 7.4 文章

- [ ] 主語と比較対象を省略しすぎていない
- [ ] 「これ」「同様」「安定」などの指示・評価語が何を指すか明確である
- [ ] 日本語と英語の混在に理由がある
- [ ] 一文に観察、原因、主張を詰め込みすぎていない
- [ ] 図のキャプションだけでも条件と結論が分かる

## 8. 今回の研究の一本線

予稿執筆中に構成が迷走した場合は、次の一本線へ戻る。

```text
粗捕捉前には光フィードバックがなく、scan-center errorが捕捉負荷を決める。
    ↓
熱変形は初期指向誤差の一部だが、日照・発熱・温度から予測できる可能性がある。
    ↓
TD/Femapにより、複数熱条件でSTT–LCT相対LOSの参照時系列を生成する。
    ↓
解析結果から、軌道内時変は面間温度差、ケース間の平均差は運用条件と対応すると観察する。
    ↓
そこで、共有感度 a_s とケースDC b_caseからなる階層型軽量モデルを構築する。
    ↓
学習ケースとLOO testを分け、熱LOS予測性能と適用限界を評価する。
    ↓
予測熱LOSをscan centerから差し引き、非熱誤差が残る条件で捕捉成功率・捕捉時間を評価する。
    ↓
熱成分は大幅に低減できるが、補正後は軌道予測誤差などが支配的となる。
    ↓
共有感度は事前固定し、条件依存DCを運用テーブルまたは捕捉後残差で更新する方針を導く。
```

この順番なら、モデルの式、PATの数値、Adaptiveの必要性が、それぞれ前段の観察と結果から導かれる。予稿では、技術項目をすべて掲載することよりも、この因果を途切れさせないことを優先する。
